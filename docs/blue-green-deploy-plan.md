# AWS Lambda Blue/Green デプロイ計画・設計

## 目的

AWS Lambda（Node.jsランタイム）に対して、CodeDeployや重み付け（カナリア／リニア）を使わないBlue/Greenデプロイを検証する。

運用方式は、次の3つのAWS機能の責務に分ける。

- SAM: 関数コードをデプロイし、`$LATEST` を更新する
- AWS CLI: バージョン発行、裏での検証、`live` エイリアスの切替を行う
- Lambda エイリアス: 本番トラフィックの宛先を旧バージョン（blue）または新バージョン（green）へ切り替える

## デプロイ方式

1. `sam deploy` を実行し、Lambda関数のコードを更新する。
2. `aws lambda publish-version` を実行し、更新済みコードのスナップショットであるgreenバージョンを発行する。
3. バージョン番号付きARNを指定してLambdaを直接invokeし、エイリアス経由ではなく裏でgreenを検証する。
4. 検証が成功した場合、`aws lambda update-alias` で `live` エイリアスをgreenへ切り替える。
5. 問題が発生した場合、同じコマンドで `live` エイリアスをblueへ戻す。

エイリアスの切替は一括かつアトミックに行われるため、カナリアやリニアの段階的移行は行わない。また、切替中のダウンタイムを前提としていない。

## バージョンとエイリアスの考え方

- blue: 切替前のバージョンであり、即時ロールバック先として保持する。
- green: `publish-version` が発行する検証対象の新バージョン。
- `live`: 本番トラフィックの宛先を表すエイリアス。
- `$LATEST`: 未発行のコード更新先。通常の本番トラフィックはこの状態に直接向けない。

`sam deploy` 後にgreenを発行する前に別のコード更新を行わないことを運用上の前提とする。並行デプロイを許可すると、発行されるgreenが想定コードと一致しない可能性があるため、デプロイ処理には排他制御を設ける。

## 運用フロー

### 共通準備

```text
AWSリージョン、関数名、IAM権限を確認する
```

必要な権限は少なくとも次を含む。

- `lambda:UpdateFunctionCode`
- `lambda:PublishVersion`
- `lambda:InvokeFunction`
- `lambda:GetAlias`
- `lambda:UpdateAlias`

権限やリソース名は環境ごとの設定として管理し、本番値をスクリプトやドキュメントへ直接記載しない。

### デプロイ

```text
SAMテンプレートとソースを変更する
sam build
sam deploy
AWS CLIで新バージョンを発行する
発行されたバージョン番号とARNを記録する
```

バージョン発行後のARNは、検証時に使うため実行結果から保存する。

### 裏での検証

バージョン番号付きARNを直接invokeする。エイリアスを指定しないため、本番トラフィックは検証invokeの影響を受けない。

検証項目は実装時にスクリプトへ組み込む。

- 正常応答を返すこと
- 想定したステータス・レスポンス形式であること
- 実行時間とメモリ使用量が許容範囲内であること
- 既存機能に対する代表的なテストケースが成功すること

検証用のペイロード、期待値、検証失敗時の判定基準はCLIスクリプトまたは設定ファイルで管理する。検証に成功するまで`live`エイリアスは変更しない。

### 切替

検証成功後、現在の`live`エイリアスがblueのバージョンを参照していることを確認し、次の順序で切り替える。

1. 現在のバージョンをblueとして保存する。
2. greenのバージョン番号を確認する。
3. `live` エイリアスをgreenへ更新する。
4. 切替後のエイリアス参照先を確認する。
5. 本番相当のスモークテストを実行する。

切替後のスモークテストは、エイリアス経由のinvokeでも確認する。

### ロールバック

切替後に問題が見つかった場合、保存したblueバージョンへ`live`エイリアスを戻す。

```text
aws lambda update-alias \
  --function-name <FUNCTION_NAME> \
  --name live \
  --function-version <BLUE_VERSION>
```

スクリプトでは失敗時に次を確認する。

- 関数名とリージョンが正しいこと
- blueバージョンが指定・存在すること
- ロールバック後のエイリアス参照先がblueであること

ロールバックにより`live`エイリアスが旧バージョンへ戻る。greenバージョン自体の削除はロールバック完了後に任意で行う。

## エラー処理

- `sam deploy`失敗時: `$LATEST`の更新内容とデプロイ状態を確認し、次のバージョン発行を行わない。
- `publish-version`失敗時: 新バージョンを変更せず、エイリアスも変更しない。
- 直接invoke失敗時: greenを本番へ切り替えず、失敗ログとレスポンスを記録する。
- エイリアス切替失敗時: 切替前の参照先を再取得し、予期しない変更がないことを確認する。
- 切替後検証失敗時: 即時ロールバックを実施する。

CLIスクリプトは失敗を検知したら中断し、成功時と失敗時のバージョン番号をログへ出力する。

## 設計上の制約

- 重み付け（カナリア／リニア）は使用しない。
- CodeDeployは使用しない。
- 本番トラフィックを`$LATEST`へ直接向けない。
- 切替単位は単一の`live`エイリアス。
- 古いバージョンはロールバックのために保持する。
- 同時デプロイを避けるため、デプロイ処理には排他制御を設ける。
